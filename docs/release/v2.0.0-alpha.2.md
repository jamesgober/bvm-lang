# bvm-lang v2.0.0-alpha.2 — Coroutines

**The VM now runs all of LSB.** alpha.2 adds the coroutine group: stackful,
asymmetric coroutines for Python and PHP generators, PHP fibers, and Mox
async tasks, with keys and return values, throwing in, closing with pending
`finally` blocks, iteration, and `spawn`/`await` through a scheduler hook. A
suspended coroutine that is dropped is closed, as PHP and Python close their
generators. Still a pre-release: the API freezes at 2.0.0 once a real
consumer (Mox) has run on it.

## What is bvm-lang?

The T1 tier of LexerSketch (ARCHITECTURE §7): the default interpreter every
language built with the `-lang` family runs on before (or instead of) native
compilation. One VM serves static languages, through typed registers and
unboxed arithmetic, and dynamic ones, through `dyn` registers, PHP-style
ordered maps, and hooks a language uses to supply its own semantics. It is an
LXRT-tier crate depending only on `bytecode-lang`.

## What's new in 2.0.0-alpha.2

### Coroutines (LSB §5.13)

`coro_new` makes a coroutine, `resume` runs it until it `yield`s, `await`s,
returns, or fails. A `yield` can sit any number of calls below the body, hook
calls included, and the whole stack between them is suspended:

```rust
use bvm_lang::{Host, Program, Value, Vm};
use bytecode_lang::{Inst, ModuleBuilder, Policy, ValType};

let d = ValType::Dyn;
let mut m = ModuleBuilder::new();
// gen() { x = yield 1; return x + 1 }
let mut g = m.function("gen", &[], &[d]);
let (one, x) = (g.reg(d), g.reg(d));
g.emit(Inst::DLoadInt { dst: one, val: 1 });
g.emit(Inst::Yield { dst: x, src: one });
g.emit(Inst::DAdd { dst: x, lhs: x, rhs: one, pol: Policy::new() });
g.ret(x);
let generator = m.add_function(g).unwrap();
let mut f = m.function("main", &[], &[d]);
let (c, a, b, sent) = (f.reg(d), f.reg(d), f.reg(d), f.reg(d));
f.emit(Inst::CoroNew { dst: c, func: generator, argc: 0 });
f.emit(Inst::Resume { dst: a, coro: c, src: sent }); // 1
f.emit(Inst::DLoadInt { dst: sent, val: 41 });
f.emit(Inst::Resume { dst: b, coro: c, src: sent }); // 42
f.emit(Inst::DAdd { dst: a, lhs: a, rhs: b, pol: Policy::new() });
f.ret(a);
let main = m.add_function(f).unwrap();
let program = Program::load(m.finish().unwrap(), &Host::new()).unwrap();
assert_eq!(Vm::new(&program).run(main, &[]), Ok(Value::Int(43)));
```

Every rule of §5.13 is implemented and tested: automatic and explicit keys
(`yield_kv`, `coro_key`, PHP's `yield $k => $v`), return values
(`coro_result`, Python's `StopIteration.value`), `resume_throw` caught by a
`try` around the `yield`, `coro_close` running pending `finally` blocks
(including `CloseIgnored` when the coroutine yields instead, and an `await`
during the close that the closer drives with `resume`), `finally` blocks that
suspend with their pending completion intact, iteration with
`iter_new`/`diter_new`, and the errors `InvalidCoroState`, `CannotSuspend`,
and `NoScheduler`.

### Close on drop (LSB §5.13 rule 13)

A suspended coroutine that becomes unreachable is closed: its pending
`finally` blocks run with the drop signal `nil`. This VM's heap is traced, so
the collection that finds the coroutine queues it, and the VM closes queued
coroutines one at a time, oldest first, at the next fuel charge point of a
run. `Vm::run_finalizers` closes them on demand (after `collect_garbage`, at
program exit). The rule itself, with both schedules (immediate for
reference-counted runtimes, queued for traced ones), is now written into LSB.

### Tasks

`Host::register_scheduler` registers a small deterministic scheduler as an
import to bind as the `spawn` hook, and `Vm::run_async` runs a function as
its main task: tasks run one at a time in FIFO order, `await` of a task waits
for its result or error, and a cycle of waiting tasks is reported as
`VmError::Deadlock`. A scheduler written in bytecode works too: bind the hook
to a module function.

### Fuel (LSB §5.14)

The fuel rule is now part of LSB, so every tier stops a run at the same pc:
safepoints, calls, hook invocations, taken backward branches, handler entries,
and every coroutine instruction each cost one unit.

### Differential testing of whole programs

A second reference interpreter (`tests/common/full.rs`) runs whole modules:
calls of every kind, closures, arrays, maps, structs, strings, try/catch,
try/finally with `return` in `finally` overriding, and coroutines (it keeps a
frame stack per coroutine, where the VM copies frames). 3,000 random
six-function modules per run must agree with the VM on their result, error
location, globals, and fuel, under random fuel and depth limits; ten of
eleven deliberately injected bugs fail it.

## Breaking changes from alpha.1

- `VmError::Unsupported` is removed; `VmError::Deadlock` is new.
- `coro_new` with the wrong argument count, or with a body that has
  captures, is now a load error.
- `call_indirect`/`tail_call_indirect` to an import check the argument count
  before charging fuel.

## Not in this release

- The verifier's type discipline (bytecode-lang 0.5).
- Host functions calling back into bytecode (host-lang); until then no host
  frame can sit between a coroutine and its `yield`, so `CannotSuspend` comes
  only from suspending with no coroutine running.
- A per-coroutine "close on drop" flag: LSB format 1 has none, so every
  suspended coroutine is closed when dropped.

## Quality

New suites: coroutine conformance (one or more tests per instruction and
rule, including exact fuel costs), the scheduler, coroutines and the
collector (tracing, close on drop, budgets), and the whole-program
differential property. Benchmarks: `foreach` over a generator (~65-69 ns per
element), 100k coroutines created and finished (~190-200 ns each), and two
tasks taking turns (~45-48 ns per `await`), on a shared Windows machine;
see the README for the full table and the comparison with alpha.1.
