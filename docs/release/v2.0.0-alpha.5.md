# bvm-lang v2.0.0-alpha.5: Fuel for Data Work, Finite Defaults

**Fuel now bounds time, not just instruction count.** Before this release one
unit of fuel paid for one charge point however much data the instructions in
between moved. A loop that concatenated two 512 KiB strings cost one unit per
iteration, the same as a loop that added 1, so a budget sized for
microseconds could run for seconds. And `Vm::new` ran with no fuel limit and
a 1 GiB heap, so the shortest path through the docs was the one that let an
endless loop run forever. Both are fixed. Still a pre-release: the API
freezes at 2.0.0.

## Data work costs fuel

An instruction now pays one more unit per 256 bytes it copies, hashes, or
compares:

- every byte it builds or copies: concatenations, slices, new arrays, a
  struct copied by `dup`, and the copy that separates shared copy-on-write
  storage;
- string keys hashed or compared in maps;
- strings compared by `str_eq`, `str_cmp`, and the string cases of the
  dynamic comparisons.

Work done inside host functions is the host's and is not charged. The work
is recorded as it happens and paid when the instruction finishes.
If the fuel left cannot pay, the run ends with `OutOfFuel` at that
instruction (which has completed). The charge is rounded down per
instruction, so one that moves less than 256 bytes costs nothing extra and
ordinary code keeps its exact fuel. The dispatch loop pays one compare per
out-of-line instruction. `Limits::with_data_fuel(false)` turns the charge
off and leaves exactly LSB §5.14's charge points, for hosts that need fuel
to match another tier and trust the code they run.

With 20,000 units of fuel, a loop that copies 128 KiB per iteration now
stops after about 37 iterations (under 5 MiB copied) instead of 20,000
(2.5 GiB).

## Finite defaults, and named presets

| preset | fuel | memory | depth | register slots |
|---|---|---|---|---|
| `Limits::untrusted()` (new) | 10,000,000 | 64 MiB | 1,000 | 1 Mi (8 MiB) |
| `Limits::new()`, `Default`, `Vm::new` | 100,000,000 | 256 MiB | 10,000 | 4 Mi (32 MiB) |
| `Limits::trusted()` (new) | unlimited | 1 GiB | 10,000 | 4 Mi (32 MiB) |

`Limits::new()` used to be what `trusted()` is now. The README, the crate
docs, and every example start from `untrusted()`.

## A hash key for `no_std` hosts

`Vm::set_hash_seed(u128)` lets a host supply the key map keys are hashed
with. With `std` every VM already gets a random key. Without it the key was
a fixed constant, and a module that knew it could pick colliding string
keys and make building a map quadratic. The call returns `false`, changing
nothing, once the heap holds a map.

## Migrating from alpha.4

- Programs that build or compare long strings, or copy large arrays and
  maps, use more fuel. A host whose budgets were exact for such code raises
  them.
- A host that relied on unlimited fuel from `Vm::new` or `Limits::new()`
  switches to `Limits::trusted()`.

## Install
