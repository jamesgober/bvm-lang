# bvm-lang v2.0.0-alpha.3 — LSB Format 2

**The VM now runs LSB format 2**, the format bytecode-lang 0.3 publishes:
dynamic calls that bind to real parameter lists (PHP's and Python's argument
rules, by-reference parameters decided at run time, host functions as
values), PHP references with transparent reference slots, copy-on-write
separation for nested writes, OPS v2's `pow`/`abs`/saturating shifts with the
family's shared `ls_pow` routine, `raise` with error payloads, and PHP's
generator keys. Every item of the "Next for bvm-lang" list in bytecode-lang's
v0.3.0 release notes is done. Still a pre-release: the reference-counting
memory profile (decision D22) comes in alpha.4, and the API freezes at 2.0.0
once a real consumer (Mox) has run on it.

## What is bvm-lang?

The T1 tier of LexerSketch (ARCHITECTURE §7): the default interpreter every
language built with the `-lang` family runs on before (or instead of) native
compilation. One VM serves static languages, through typed registers and
unboxed arithmetic, and dynamic ones, through `dyn` registers, PHP-style
ordered maps, and hooks. It is an LXRT-tier crate depending only on
`bytecode-lang`.

## What's new in 2.0.0-alpha.3

### Dynamic calls with parameter lists (LSB §5.15)

`dcall` and the new `dcall_shape` bind a call site's arguments (positional,
named, spread, named spread) to the callee's parameter list: positional-only,
normal, named-only, rest, rest map, and named rest parameters, `ignore_extra`
for PHP user functions, defaults computed by the callee from a presence mask,
and by-reference parameters, which receive a reference (a temporary for a
non-reference argument). Binding errors are `ArgumentError` (E0114) and cost
no fuel; the call is charged once its arguments bind. `dparam_ref` and
`dparam_ref_named` tell a PHP code generator, before it evaluates an
argument, whether the callee takes it by reference. `coro_new_indirect` and
`spawn` bind the same way, and `dcall_shape` on a non-callable reaches the new
`call_shape` hook. All-positional calls bind without allocating, through a
binder property-tested against `bytecode_lang::ParamList::bind`; calls with
names use `ParamList::bind` itself.

`load_import` makes any import a function value. Imports carry parameter
lists too, so `array_push(&$array, ...$values)` or `printf($format, ...$args)`
can be host functions passed around and called with spreads and named
arguments; `HostCtx::ref_get`/`ref_set`/`elements`/`entries`/`new_array`/
`new_map` give host functions what they receive.

### References (LSB §5.17)

`new_ref`, `dref_index`/`dref_prop` (`&$a['k']`, `foreach ($a as &$v)`),
`dbind_index`/`dbind_prop` (`$a['k'] = &$x`), and `dunref_index`/
`dunref_prop`. A slot holding a reference is transparent to every value read
and write, typed or dynamic, and to the host and inspection APIs; copies of a
container share its reference slots, as PHP's do. A reference word carries a
flag bit, so the transparency check is one compare on a word the access
already loaded.

### Separation (LSB §5.16)

`dsep_index`/`dsep_prop` make an element safe to write in place, copying it
only when another container may share it, using the spec's two-bit
implementation for tracing collectors (`cow`, `aliased`). The decisions follow
the bits, not reference counts or collection timing, so they are
deterministic. PHP's `$g[$i % 64][] = $i` now copies no contents after its
first pass: in the benchmark it runs ~40x faster than the `dup`-per-write
lowering format 1 required (~11-16 ms against ~540-575 ms for 100k appends
on a loaded machine).

### OPS v2 and the shared `ls_pow`

`ipow` (exact, every integer type and overflow policy, `NegativeExponent`
E0006), `fpow`, `dpow` (`promote` rounds the exact power; PHP's `2 ** -1` is
`0.5`), `dabs` (`abs(PHP_INT_MIN)` under `promote`), and `shift = saturate`
(PHP's `<<`/`>>`). Float powers use `ls_pow`, which this milestone specifies
operation by operation in `_lexersketch/specs/ops-vectors/pow.md`
(double-double logarithm and exponential, an exact integer path for every
midpoint an integer exponent can produce, constants as bit patterns, a
122-row vector table) so that every tier can copy it bit for bit. An
independent Python transcription agrees with the Rust one on 200,000 inputs,
and all 190,012 finite non-special results among them are correctly rounded
against an exact oracle; the routine is correctly rounded except within
about 2^-85 of a rounding boundary (one such case is in the table).

### Errors with payloads, generator keys

`raise kind, src` raises any catchable kind with a payload, read by
`err_payload`, `Vm::error_payload`, and `VmError::Raised { payload }`: how a
code generator raises `NoMatch` (E0200) with the unmatched value. Generator
keys follow PHP: after only `yield -5 => x` the next automatic key is `0`.

## Breaking changes from alpha.2

- `bytecode-lang` `0.3`; format 1 bytes are refused (`UnsupportedVersion(1)`).
  `Inst::INot` is `IBitNot`, the bitwise `Inst::DNot` is `DBitNot`,
  `Inst::DLNot` is `DNot`; `F32ToInt`/`F64ToInt` take a `FloatConv`.
- `VmError::Raised` has a `payload` field.
- Dynamic-call arity mismatches are `ArgumentError`, not `TypeError`.
- The automatic generator key after only negative explicit keys is `0`.
- `dup` of a reference is a `TypeError`; `LoadErrorKind` gains
  `BadParamList` and `BadCallShape`.

## Not in this release

- The reference-counting memory profile (D22): PHP's dropping of a
  refcount-1 reference when an array is copied, and deterministic destructor
  and close-on-drop timing, need counts a tracing heap does not keep. LSB
  keeps a reference slot until `dunref_*` unbinds it (the divergence LSB §5.17
  documents); alpha.4 adds the profile behind the seam this release leaves
  (`contents_shared` on arrays and maps, `Heap::is_aliased`).
- The verifier's type discipline (bytecode-lang 0.5) and host re-entrancy
  (host-lang), as before.

## Quality

New suites: `tests/php_semantics.rs` (23 PHP programs lowered as a PHP code
generator lowers them, each with the result PHP 8.3 gives: value semantics
and separation, references in variables, slots, `foreach`, and copies, named
arguments, variadics, by-reference arguments decided at run time, host
functions as values, `pow`/`abs`/shifts, generator keys, `match` without an
arm), `tests/format2.rs` (18: loading, format 1 refused, parameter lists and
call shapes checked, the `call_shape`/`call` hooks, flattening errors before
hooks, the fuel point of a dynamic call, `dparam_ref` for every parameter
kind, coroutine binding, payloads, references and payloads surviving
collections, reference and separation corner cases), and
`tests/pow_vectors.rs` (the spec's 122 `ls_pow` vectors through `fpow` and
`dpow`). Both differential references were extended: the scalar one with
`ipow`, `dpow`, `dabs`, saturating shifts, and `fpow` (with its own
transcription of `ls_pow` from the spec), the whole-module one with every
format 2 feature, written from the spec (its own §5.15 binder, its own model
of the two copy-on-write bits, reference slots), plus a new PHP-focused
property over long container, reference, and dynamic-call programs. The
positional binder is property-tested against `ParamList::bind`.

Mutation-checked: 32 deliberate bugs in the new code (binding, flattening,
separation, `cow` marking, references, unbinding, write-through, payloads,
tracing of references and payloads, `ls_pow`, `abs`, the loader's checks,
generator keys); every one that changes behaviour fails the suite. Three
had no observable effect and were set aside as equivalent: a key-rule
variant that cannot trigger, a redundant container write (since removed),
and a last-bit change to the `1/720` series coefficient, which is below the
routine's double-double precision.

Totals with all features: 44 unit tests, 255 integration tests in 18 files,
and 99 doctests (every `rust` example in `README.md` and `docs/API.md`
included).

## Performance

The alpha.2 regression of `call/fib25` is isolated and fixed: `finish`
matched every continuation (the coroutine body's included) before writing a
typed call's result. Testing that continuation first makes `fib(25)` ~7%
faster than alpha.1 and ~12% faster than alpha.2 (minimum of 50 runs per
process, processes alternated: ~3.81-4.04 ms against ~4.11-4.34 ms and
~4.38-4.42 ms). The same method caught `map_set` running ~15% slower with
its reference-slot check as a separate lookup; folded into the one lookup it
is within ~2-3% of alpha.2. Dynamic calls: ~132-145 ns per positional call
to a PHP-style function with a default and a variadic (an empty rest map is
allocated per call, as the spec requires), ~261-268 ns with named
arguments, against ~74-83 ns to a function without a parameter list (100k
calls, loop included, loaded machine). The README has the full table.
